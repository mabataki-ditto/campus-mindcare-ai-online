🔍 代码Review总结

优点

✅ 统一响应格式：所有接口使用 success/fail/unauthorized 统一包装，前端处理一致
✅ 权限分层清晰：authMiddleware（登录校验）+ adminMiddleware（管理员校验），按需组合
✅ AI情绪分析自动化：风险等级≥2自动创建预警记录+更新用户风险等级，形成闭环
✅ 种子数据完善：提供完整的初始数据（账号、角色、菜单、分类），开箱即用
✅ AI代理透传：/api/ai/chat 支持流式/非流式/Function Calling，为前端切换后端代理做好准备

需要关注的问题

❌ JWT Secret 硬编码默认值：config.jwtSecret 默认值为 'default-secret'，生产环境必须通过环境变量覆盖，否则存在严重安全隐患
⚠️ Token 字段非标准：使用 req.headers['token'] 而非标准的 Authorization: Bearer xxx，不符合 RESTful 规范，且与第三方工具（Swagger/Postman）不兼容
⚠️ 前端直连DeepSeek API Key暴露：当前前端直接调用 DeepSeek API，API Key 通过 VITE_DEEPSEEK_API_KEY 暴露在前端代码中。应切换到后端代理 /api/ai/chat
⚠️ 情绪分析无频率限制：forceRefresh=true 时每次对话后都调用 DeepSeek API 重新分析，无频率限制，可能导致 API 费用过高。建议加缓存或限制分析频率
⚠️ 删除操作无软删除：会话、日记、文章删除都是物理删除（prisma.xxx.delete），数据无法恢复。建议增加 deletedAt 字段做软删除
⚠️ 会话列表缺少风险等级：GET /sessions 返回的 riskLevel 默认为0，实际风险等级来自 SessionEmotion/AlertEvent，前端需要额外映射。建议后端直接关联查询最新风险等级
⚠️ 文件上传无类型校验：multer 只限制了文件大小，没有校验文件类型（MIME type），可能上传恶意文件
⚠️ 数据库连接池偏小：connectionLimit: 5 在并发场景下可能不够，建议根据业务量调整

优先级建议说明
P0切换到后端AI代理前端直连DeepSeek暴露API Key，应改用 /api/ai/chat 代理
