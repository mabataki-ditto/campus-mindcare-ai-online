# 校园AI心理陪伴平台 — 后端接口开发流程

## 技术选型

| 技术     | 选择                  | 说明                           |
| -------- | --------------------- | ------------------------------ |
| 运行时   | Node.js 18+           | 前端开发者友好                 |
| 框架     | Express + TypeScript  | 轻量、生态丰富                 |
| 数据库   | MySQL 8.0             | 关系型，适合结构化数据         |
| ORM      | Prisma                | 类型安全、自动迁移、开发体验好 |
| 认证     | JWT (jsonwebtoken)    | 无状态，前后端分离友好         |
| 文件存储 | 本地磁盘 + 静态服务   | 简单可靠，后期可迁移 OSS       |
| AI代理   | 后端转发 DeepSeek API | 保护 API Key 不暴露            |

## 三、统一响应格式

前端响应拦截器期望的格式：

```typescript
// src/utils/response.ts
interface ApiResponse<T = any> {
  code: number // 200=成功, -1=token过期, 其他=业务错误
  msg: string
  data: T
  success?: boolean
}

function success<T>(data: T, msg = '操作成功'): ApiResponse<T> {
  return { code: 200, msg, data, success: true }
}

function fail(msg = '操作失败', code = 500): ApiResponse<null> {
  return { code, msg, data: null, success: false }
}

function unauthorized(msg = '登录过期，请重新登录'): ApiResponse<null> {
  return { code: -1, msg, data: null, success: false }
}
```

**前端拦截器行为**（必须匹配）：

- `code === 200 || success === true` → 返回 `data` 字段
- `code === -1` → 清除 token，跳转登录页
- 其他 → 弹出 `msg` 错误提示

## 四、JWT 认证中间件

```typescript
// src/middleware/auth.ts
import { Request, Response, NextFunction } from 'express'
import jwt from 'jsonwebtoken'
import { unauthorized, fail } from '../utils/response'

export function authMiddleware(req: Request, res: Response, next: NextFunction) {
  const token = req.headers['token'] as string // 前端传的是 header.token

  if (!token) {
    return res.json(unauthorized('未提供认证令牌'))
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET!)
    ;(req as any).user = decoded
    next()
  } catch {
    return res.json(unauthorized('登录过期，请重新登录'))
  }
}

// 管理员权限校验
export function adminMiddleware(req: Request, res: Response, next: NextFunction) {
  const user = (req as any).user
  if (user.userType !== 2) {
    return res.json(fail('无管理员权限', 403))
  }
  next()
}
```

## 五、接口开发详细文档

### 5.1 用户模块

#### POST `/api/user/login` — 登录

```
请求：
{
  "username": "string",
  "password": "string"        // 前端传明文，后端 bcrypt 比对
}

响应：
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "userInfo": {
      "id": 1,
      "username": "admin",
      "nickname": "管理员",
      "userType": 2,
      "avatar": "https://...",
      "riskLevel": 0
    },
    "menus": [                 // 仅管理员返回
      {
        "id": 1,
        "parentId": 0,
        "name": "数据分析",
        "type": 1,
        "icon": "Dashboard",
        "path": "/main/dashboard",
        "children": [...]
      }
    ]
  }
}
```

**后端逻辑**：

1. 根据 username 查询用户
2. bcrypt.compare 比对密码
3. 生成 JWT token（payload: `{ userId, username, userType }`）
4. 管理员（userType=2）查询角色关联的菜单树返回
5. 更新用户最后登录时间

#### POST `/api/user/add` — 注册

```
请求：
{
  "username": "string",       // 必填，唯一
  "password": "string",       // 必填
  "email": "string?",         // 可选
  "nickname": "string?",      // 可选
  "phone": "string?",         // 可选
  "gender": 0|1|2?,           // 可选，0=未知 1=男 2=女
  "userType": 1|2?            // 可选，默认1
}

响应：
{
  "code": 200,
  "msg": "注册成功",
  "data": { "userId": 5 }
}
```

**后端逻辑**：

1. 检查 username 是否已存在
2. bcrypt.hash 加密密码
3. 插入用户记录
4. 默认分配"普通用户"角色

#### POST `/api/user/logout` — 登出

```
请求头：token: xxx
请求体：无

响应：
{ "code": 200, "msg": "登出成功", "data": null }
```

**后端逻辑**：可将 token 加入黑名单（Redis），简单实现可直接返回成功。

### 5.2 心理咨询模块

#### POST `/api/psychological-chat/session/start` — 创建会话

```
请求头：token: xxx
请求：
{
  "initialMessage": "string?",   // 用户首条消息

{

  "data": {

```

**后端逻辑**：

1. 从 token 获取 userId
2. 生成唯一 sessionId（`session_${timestamp}_${random}`）
3. 如果有 initialMessage，同时插入一条用户消息到 ChatMessage
4. 返回 sessionId 和 status

#### GET `/api/psychological-chat/sessions` — 会话列表

```
请求头：token: xxx
查询参数：
  - userId?: number        // 前台传，只查自己的
  - currentPage?: number   // 后台管理用，默认1
  - size?: number          // 后台管理用，默认10
  - pageNum?: number       // 前台会话列表用，默认1（兼容两种参数名）
  - pageSize?: number      // 前台会话列表用，默认10

响应（后台管理端期望格式）：
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "records": [
      {
        "id": 1,
        "sessionId": "session_xxx",
        "sessionTitle": "小暖AI助手 - 2024/3/1",
        "sessionPreview": "我最近心情不好...",    // 最后一条消息摘要（前50字）
        "messageCount": 15,                       // 消息总数
        "lastMessageTime": "2024-03-01T10:30:00Z", // 最后消息时间
        "userNickname": "小明",                   // 用户昵称（扁平化，不是嵌套user对象）
        "status": "ACTIVE",
        "createdAt": "2024-03-01T10:00:00Z",
        "alertCount": 0                           // 该会话的预警次数
      }
    ],
    "total": 25
  }
}
```

**后端逻辑**：

1. 同时支持 `currentPage/size` 和 `pageNum/pageSize` 两种分页参数名
2. 管理员不传 userId → 查所有用户会话
3. 普通用户传 userId → 只查自己的
4. 关联查询：用户昵称、消息计数、最后消息内容和时间
5. sessionPreview 取最后一条消息内容截取前50字符

## 九、前端对接关键注意事项（必读）

### 9.1 响应格式必须严格匹配

前端响应拦截器（`src/service/request/index.ts`）的判断逻辑：

```typescript
// 成功判断
if (data.code == 200 || data.success) {
  return data.data // 只返回 data 字段给业务代码
}

// token 过期判断
if (data.code == -1) {
  // 清除本地缓存，跳转登录页
  localCache.removeCache(LOGIN_TOKEN)
  window.location.href = '/auth/login'
}

// 其他错误
ElMessage.error(data.msg || data.message || '请求失败')
```

**后端必须保证**：

- 成功响应：`{ code: 200, msg: "...", data: {...}, success: true }`
- token 过期：`{ code: -1, msg: "登录过期", data: null }`
- 业务错误：`{ code: 500, msg: "错误原因", data: null }`

### 9.2 Token 传递方式

前端请求拦截器将 token 放在 **header 的 `token` 字段**（不是 Authorization）：

```typescript
const token = localCache.getCache(LOGIN_TOKEN)
if (token) {
  config.headers['token'] = token // 注意：是 'token' 不是 'Authorization'
}
```

**后端中间件必须从 `req.headers['token']` 获取**。

### 9.3 分页参数兼容

前端存在两种分页参数命名：

| 页面                                               | 参数名                |
| -------------------------------------------------- | --------------------- |
| 后台管理页面（consultation, emotional, knowledge） | `currentPage`, `size` |
| 前台会话列表（useConsultationSessions.js）         | `pageNum`, `pageSize` |
| 前台知识库（frontendKnowledge.vue）                | `currentPage`, `size` |

**后端需同时支持两种参数名**：

```typescript
const page = Number(req.query.currentPage || req.query.pageNum || 1)
const pageSize = Number(req.query.size || req.query.pageSize || 10)
```

### 9.4 字段映射关系

| 前端提交字段             | 后端存储字段                | 说明                       |
| ------------------------ | --------------------------- | -------------------------- |
| `dominantEmotion`        | `moodLabel`                 | 情绪日记主要情绪           |
| `diaryContent`           | `content`                   | 情绪日记内容               |
| `sleepQuality`（字符串） | `sleepQuality`（整数）      | 前端传 "1"/"2"，后端转整数 |
| `stressLevel`（字符串）  | `stressLevel`（整数）       | 同上                       |
| `tags`（逗号分隔）       | `tags` → `tagArray`（数组） | 返回时解析为数组           |

### 9.5 返回结构扁平化

前端期望**扁平化字段**，不要嵌套对象：

| 接口     | 前端期望               | 错误示例                     |
| -------- | ---------------------- | ---------------------------- |
| 会话列表 | `userNickname: "小明"` | `user: { nickname: "小明" }` |
| 日记列表 | `userNickname: "小明"` | `user: { nickname: "小明" }` |

### 9.6 文件路径处理

前端会拼接 `VITE_FILE_BASE_URL`：

```javascript
// 前端代码（frontendKnowledge.vue 第100行）
const getImage = (url) => {
  return url ? import.meta.env.VITE_FILE_BASE_URL + url : '默认图片'

```

**后端返回相对路径**：`/uploads/article/cover_xxx.jpg`
**前端拼接完整URL**：`http://xxx:1235/uploads/article/cover_xxx.jpg`

开发完成后，逐项验证：

- [ ] 登录接口返回 `{ token, userInfo }`，前端能正确存储
- [ ] token 过期返回 `code: -1`，前端能正确跳转登录页
- [ ] 会话列表返回 `userNickname`（扁平化），不是嵌套对象
- [ ] 会话列表包含 `sessionPreview`, `messageCount`, `lastMessageTime`
- [ ] 情绪日记接受 `dominantEmotion` 和 `diaryContent` 字段
- [ ] 文件上传返回相对路径，前端拼接后可访问
- [ ] 分页同时支持 `currentPage/size` 和 `pageNum/pageSize`
- [ ] 文章详情返回 `tagArray` 数组格式
- [ ] 消息列表 `senderType` 为 1 或 2
