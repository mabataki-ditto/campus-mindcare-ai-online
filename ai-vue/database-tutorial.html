🗄️ 什么是数据库

把数据库想象成一个超级Excel文件。每个"表"就是一个Sheet，每行是一条记录，每列是一个字段。但数据库比Excel强大得多：支持多人同时操作、快速搜索、数据关联、安全控制。

本项目用的数据库：MariaDB

MariaDB 是 MySQL 的升级版，完全兼容 MySQL 语法，性能更好、免费开源。

数据库中的核心概念

概念类比Excel说明
数据库 Database整个Excel文件本项目数据库名：ai_psychological
表 Table一个Sheet如 User表、ChatMessage表，共10个表
行 Row一行数据如一个用户、一条消息
列 Column一列（字段）如 username、password
主键 Primary Key行号唯一标识一行数据，如 id = 1
外键 Foreign Key跨Sheet引用如消息表的 sessionId 引用会话表的 id
索引 Index目录/排序加速查找，就像书的目录
传统方式写SQL：SELECT * FROM User WHERE username = 'admin'。本项目用 Prisma ORM，不需要手写SQL！

🔄 什么是ORM

ORM（对象关系映射）就像一个翻译官。你用JavaScript/TypeScript写代码，ORM自动帮你翻译成SQL语句发给数据库。你不需要学SQL语法！
❌ 传统方式（手写SQL）
// 查询用户
db.query(
  "SELECT * FROM User WHERE id = ?",
  [userId]
)

// 插入数据
db.query(
  "INSERT INTO User (username, password) VALUES (?, ?)",
  [username, password]
)
✅ Prisma ORM（本项目）
// 查询用户
const user = await prisma.user.findUnique({
  where: { id: userId }
})

// 插入数据
const user = await prisma.user.create({
  data: { username, password }
})

Prisma 的优势

  • 类型安全：写错字段名，编译器直接报错，不会到运行时才发现
  • 自动补全：编辑器会提示所有可用的字段和方法
  • 不用写SQL：Prisma自动生成最优SQL语句
  • 数据库无关：换数据库（MySQL→PostgreSQL）只需改一行配置
  • 可视化工具：npx prisma studio 打开网页直接查看/编辑数据

📝 字段语法详解

以 User 表为例，逐行解释每个字段的语法：

model User {
  // 字段名    类型     修饰符（约束条件）
  id        Int      @id @default(autoincrement())  // 主键，自增
  username  String   @unique @db.VarChar(50)         // 唯一，最长50字符
  password  String   @db.VarChar(255)                // 最长255字符
  nickname  String?  @db.VarChar(50)                 // 可空（?表示可选）
  gender    Int?     @default(0)                     // 可空，默认值0
  userType  Int      @default(1)                     // 必填，默认值1
  createdAt DateTime @default(now())                 // 创建时间，默认当前时间
  updatedAt DateTime @updatedAt                      // 更新时间，自动更新
}

常用修饰符

修饰符含义标签示例
@id主键（唯一标识一行）PKid Int @id
@default(autoincrement())自增（1,2,3...）自增id Int @id @default(autoincrement())
@unique唯一约束（不能重复）UNIQUEusername String @unique

🔗 关系语法详解

关系就像Excel中"跨Sheet引用"。比如消息表需要知道"这条消息属于哪个会话"，就通过外键 sessionId 引用会话表的 id。

一对多关系（最常见）

一个用户可以有多个会话，一个会话属于一个用户：

model User {
  id       Int                   // 主键
  sessions ConsultationSession[] // ← "一个用户有多个会话"（数组表示多个）
}

model ConsultationSession {
  id     Int   // 主键
  userId Int   // ← 外键：引用User.id

  // 关系定义：sessionId 引用 User.id
  user User @relation(fields: [userId], references: [id])
}

关系语法拆解

语法含义在哪一端
sessions ConsultationSession[]一个User有多个Session"一"端（User）
user User @relation(fields: [userId], references: [id])Session的userId字段引用User的id"多"端（Session）
记住口诀："多方加外键，一方加数组"。多方（Session）加 userId 外键和 @relation，一方（User）加 sessions Session[] 数组。

多对多关系（通过中间表）

用户和角色是多对多：一个用户可以有多个角色，一个角色可以属于多个用户。

model UserRole {
  userId Int // 外键→User.id
  roleId Int // 外键→Role.id

  user User @relation(fields: [userId], references: [id])
  role Role @relation(fields: [roleId], references: [id])

  @@id([userId, roleId])  // 联合主键（两列一起唯一）
}
@@id([userId, roleId]) 是联合主键，表示 userId+roleId 的组合必须唯一。一个用户不能被分配同一个角色两次。

可选关系（可空外键）

预警事件不一定关联会话：

model AlertEvent {
  sessionId  Int?   // 可空外键（?表示可以没有关联会话）
  session    ConsultationSession? @relation(fields: [sessionId], references: [id])
  //         ↑ 注意这里也有?，表示关系是可选的
}

📖 索引语法

索引就像书的目录。没有目录，找"焦虑症"要翻遍整本书；有了目录，直接翻到对应页码。数据库索引同理，加速查找。
model ChatMessage {
  id        Int
  sessionId Int
  content   String

  session ConsultationSession @relation(fields: [sessionId], references: [id])

  @@index([sessionId])  // 在 sessionId 上建索引
  // ↑ @@ 表示模型级别（表级别）的注解
  // @  表示字段级别的注解
}

本项目中的索引

表索引字段为什么需要
ChatMessagesessionId按会话查消息（最频繁的查询）
SessionEmotionsessionId按会话查情绪
AlertEventuserId, riskLevel, handled按用户查预警、按等级筛选、按处理状态筛选
EmotionDiaryuserId, diaryDate按用户查日记、按日期范围查询
KnowledgeArticlecategoryId, status按分类查文章、按状态筛选
索引会加速查询，但会略微降低写入速度（因为每次插入都要更新索引）。所以只在经常用来查询/筛选的字段上加索引，不要滥用。

👤 User 用户表

model User {
  id        Int      @id @default(autoincrement())  // 主键，自增1,2,3...
  username  String   @unique @db.VarChar(50)         // 用户名，唯一，最长50
  password  String   @db.VarChar(255)                // 密码（bcrypt加密后存储）
  nickname  String?  @db.VarChar(50)                 // 昵称，可选
  email     String?  @db.VarChar(100)                // 邮箱，可选
  phone     String?  @db.VarChar(20)                 // 手机号，可选
  gender    Int?     @default(0)                     // 性别：0未知 1男 2女
  avatar    String?  @db.VarChar(500)                // 头像URL
  userType  Int      @default(1)                     // 角色：1普通用户 2管理员
  riskLevel Int      @default(0)                     // 风险：0正常 1关注 2预警 3危机
  status    Int      @default(1)                     // 状态：1正常 0禁用
  createdAt DateTime @default(now())                 // 创建时间
  updatedAt DateTime @updatedAt                      // 更新时间（自动）

  // 关系：一个用户有...
  sessions    ConsultationSession[]  // 多个咨询会话

  alertEvents AlertEvent[]           // 多个预警事件

字段解读

字段类型说明
passwordVARCHAR(255)不是明文！用 bcrypt 加密后存储，如 $2a$10$N9qo8uLOickgx2ZMRZoMy...
userTypeInt1=普通用户（学生），2=管理员（老师）。决定能访问哪些功能

💬 ConsultationSession 咨询会话表

model ConsultationSession {
  id           Int      @id @default(autoincrement())
  sessionId    String   @unique @db.VarChar(100)  // 业务ID，如 session_1746_xxx
  userId       Int                         // 外键→User.id
  sessionTitle String?  @db.VarChar(200)   // 会话标题
  status       String   @default("ACTIVE") @db.VarChar(20) // TEMP/ACTIVE/ENDED
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  // 关系
  user     User              @relation(fields: [userId], references: [id])
  messages ChatMessage[]     // 一个会话有多条消息
  emotions SessionEmotion[]  // 一个会话有多条情绪记录
  alerts   AlertEvent[]      // 一个会话可能有多个预警
}

为什么有两个ID？

id 是数据库内部用的自增编号（1,2,3...）。sessionId 是业务ID（如 session_1746035123456_abc123），暴露给前端使用，防止别人猜到其他会话的ID。

会话状态流转

TEMP（临时）
→
ACTIVE（进行中）
→
ENDED（已结束）

用户打开聊天页面时创建TEMP会话，发送第一条消息后变为ACTIVE。

💭 ChatMessage 聊天消息表

model ChatMessage {
  id         Int      @id @default(autoincrement())
  sessionId  Int                        // 外键→ConsultationSession.id
  senderType Int                        // 1=用户发的, 2=AI回复的
  content    String   @db.Text          // 消息内容（可很长）
  createdAt  DateTime @default(now())

  session ConsultationSession @relation(fields: [sessionId], references: [id])

  @@index([sessionId])  // 加速按会话查消息
}
senderType 用数字而非字符串，是因为数字比较更快、存储更小。1=用户、2=AI 是项目约定。

model AlertEvent {

🔐 RBAC权限模型（5张表）

RBAC = Role-Based Access Control（基于角色的访问控制）。就像学校里：学生→只能看课表，老师→能改成绩，校长→能管一切。用户不直接分配权限，而是分配"角色"，角色拥有"菜单权限"。
User 用户
→
UserRole 用户角色
→
Role 角色
→
RoleMenu 角色菜单
→
Menu 菜单

举例：用户 admin → UserRole → Role(admin) → RoleMenu → Menu(数据分析、知识文章、AI陪伴记录、心情档案)

Menu 菜单表的树形结构

菜单用 parentId 实现树形：

// 一级菜单（parentId = 0）
{ id: 1, name: "数据分析", parentId: 0, type: 1 }

// 二级菜单（parentId = 父菜单id）
{ id: 2, name: "知识文章", parentId: 0, type: 2 }
{ id: 3, name: "AI陪伴记录", parentId: 0, type: 2 }

1. Create — 创建（插入数据）

// 创建一个用户
const user = await prisma.user.create({

2. Read — 查询（读取数据）

// 按主键查一条
const user = await prisma.user.findUnique({
  where: { id: 1 }
})

// 按唯一字段查一条
const user = await prisma.user.findUnique({
  where: { username: 'admin' }
})

// 按条件查第一条
const session = await prisma.consultationSession.findFirst({
  where: { sessionId: 'session_xxx' }
})

// 查多条（列表）
const messages = await prisma.chatMessage.findMany({
  where: { sessionId: 1 },
  orderBy: { createdAt: 'asc' },  // 按时间正序
  take: 20                        // 最多取20条
})

// 统计数量
const count = await prisma.user.count({
  where: { status: 1 }
})

3. Update — 更新

// 更新单条
await prisma.user.update({
  where: { id: userId },
  data: { riskLevel: 3 }
})

// 更新多条
await prisma.alertEvent.updateMany({
  where: { handled: false },
  data: { handled: true, handledAt: new Date() }
})

// 自增操作（阅读量+1）
await prisma.knowledgeArticle.update({
  where: { id: articleId },
  data: { readCount: { increment: 1 } }
})

4. Delete — 删除

// 删除单条
await prisma.emotionDiary.delete({
  where: { id: diaryId }
})

// 删除多条
await prisma.chatMessage.deleteMany({
  where: { sessionId: sessionId }
})

🔍 高级查询

关联查询（include）

// 查会话时，同时带出用户信息和消息数量
const sessions = await prisma.consultationSession.findMany({
  include: {
    user: { select: { nickname: true, username: true } },
    _count: { select: { messages: true } },
    alerts: { select: { id: true } }
  }
})
// 返回结果中会多出 user, _count, alerts 字段

条件组合（where）

// AND 条件
await prisma.alertEvent.findMany({
  where: {
    handled: false,
    riskLevel: { gte: 2 }  // gte = 大于等于
  }
})

// OR 条件
await prisma.user.count({
  where: {
    OR: [
      { diaries: { some: { createdAt: { gte: thirtyDaysAgo } } } },
      { sessions: { some: { createdAt: { gte: thirtyDaysAgo } } } }
    ]
  }
})

    where: { userId },
    orderBy: { createdAt: 'desc' },  // 按时间倒序
    skip: (page - 1) * size,        // 跳过前N条
    take: size                       // 取N条
  }),
  prisma.emotionDiary.count({ where: { userId } })
])

🔄 事务（Transaction）

事务就像银行转账：A扣钱和B加钱必须同时成功，不能A扣了B没加。事务保证"要么全部成功，要么全部回滚"。
// 删除会话时，需要同时删除关联的消息、情绪、预警
await prisma.chatMessage.deleteMany({ where: { sessionId: session.id } })
await prisma.sessionEmotion.deleteMany({ where: { sessionId: session.id } })
await prisma.alertEvent.deleteMany({ where: { sessionId: session.id } })
await prisma.consultationSession.delete({ where: { id: session.id } })

// 更严谨的写法：用事务包裹（任一步失败则全部回滚）
await prisma.$transaction([
  prisma.chatMessage.deleteMany({ where: { sessionId: session.id } }),
  prisma.sessionEmotion.deleteMany({ where: { sessionId: session.id } }),
  prisma.alertEvent.deleteMany({ where: { sessionId: session.id } }),
  prisma.consultationSession.delete({ where: { id: session.id } })
])

🚚 数据库迁移（Migration）

迁移就像版本控制（Git），每次修改表结构都生成一个迁移文件，记录"做了什么改动"。可以回滚到任意版本。
# 1. 修改 schema.prisma（比如给 User 加一个 phone 字段）

# 2. 创建迁移
npx prisma migrate dev --name add_user_phone

# 这会做3件事：
# ① 在 prisma/migrations/ 下生成一个SQL文件
# ② 执行这个SQL文件，修改数据库表结构
# ③ 重新生成 Prisma 客户端代码

# 3. 查看生成的SQL（可以学习SQL语法）
# prisma/migrations/20260604_add_user_phone/migration.sql：
# ALTER TABLE `User` ADD `phone` VARCHAR(20) NULL;
